# ADR 0013：技能 Playbook、设计上下文包与只读设计工具

- 状态：已采纳
- 日期：2026-10-22
- 相关：ADR 0004（AI 工具调用）、ADR 0006（上下文摘要）、ADR 0010（Agent 循环）

## 背景

早期技能只是“提示词片段 + 关键词”，模型知道“画图”，但不知道按什么步骤做、做完检查什么；
上下文只统计类型、图层与包围盒，模型看不到图层可见性、块、标注覆盖与修订号；
“这条线多长”“有没有未闭合轮廓”这类问题只能靠模型从坐标心算，结果不可复核。

## 决策

1. **技能升级为 Playbook**
   - `ai_skills` 增加 `steps` / `checks` / `examples` / `required_context` / `negative_keywords` / `version`。
   - 系统技能种子包含 2–4 个执行步骤、完成检查与示例请求；promptComposer 按固定小标题注入，单技能块 1400 字符上限。
   - 技能面板可编辑上述字段；每次更新 `version += 1`，用于追踪提示词版本。

2. **路由先判断意图，再放大信号**
   - 关键词、显式固定、助手绑定、会话连续性构成“语言意图”。
   - 选择集类型与 `requiredContext`（选择集 / 多图层 / 块 / 修订号 / 尺寸标注）只在已有意图时加分；
     否则“选中一条线”会同时激活编辑、阵列等所有包含 LINE 的技能。
   - 负关键词命中扣分，用于排除明显不适用的场景。
   - 任一技能的工具全部属于只读集合时，本轮可用工具收敛为该只读技能的工具集；
     审查模式不会因为同时命中编辑技能而拿到写工具。

3. **三档设计上下文包**
   - `brief`：统计、项目/单位、图层名、包围盒、选中 id（≤10），用于小图短指令。
   - `standard`：增加图层可见性/锁定、块引用数、标注覆盖、隐藏对象数、修订号与最多 10 个选中图元几何。
   - `deep`：选中图元扩展到 30 个、图层扩展到 32 个，用于审查/测量/布局类问题或 >150 图元的图纸。
   - 档位由 `chooseContextTier` 按问题关键词与图纸规模确定；结构化字段同时通过 `canvasContext` 发送，
     供技能路由与提示词使用。仍禁止发送完整图元 JSON。

4. **三个只读设计工具**
   - `query_elements`：按类型、图层、文本、包围盒查询，返回 id 与轻量几何摘要。
   - `measure_geometry`：距离 / 总长度 / 面积 / 包围盒，基于真实几何计算。
   - `check_drawing`：零长度、非法圆、退化矩形、重复、近似闭合、缺失标注的确定性检查。
   - 前端在 Agent 草稿上执行（`lib/readOnlyTools.ts`），结果序列化到 1800 字符以内且有界裁剪，
     避免后端 2000 字符 toolResult 上限把 JSON 截断成非法内容。

## 后果

- 模型先查询/测量/检查再回答，尺寸与审查结论可复现，不依赖心算。
- 技能 prompt 更结构化，但注入内容变多；靠单技能 1400 字符与技能数量上限（3）控制成本。
- 上下文包按档位增长，审查类请求上下文更大，但只在需要时发生。
- 新增工具名必须同步后端 `tools.ts`、前端 `lib/aiTools.ts`、工具夹具与设计任务评测；
  `backend/tests/toolCalls.test.ts` 与 `tests/aiTools.test.ts` 锁定数量。
