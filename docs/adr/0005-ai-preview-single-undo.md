# ADR 0005：AI 动作先预览后应用，合并为单次撤销

- **状态**：Accepted
- **日期**：2026-10-21
- **决策者**：AI 与前端团队

## 背景

AI 一次回复可能包含多个工具调用。早期实现边解析边写画布：用户看到的是已经发生的修改，无法在写入前判断结果；多步操作还会产生多条撤销记录，`CLEAR` 与批量删除更是不可逆的高风险动作。

## 决策

1. AI 动作先在内存中 dry-run：`lib/aiActions.ts` 的 `computeAIActionOutcome` 基于当前元素快照计算最终结果，不触碰画布状态。
2. 前端用 `AIPreviewModal` 展示“将新增 / 修改 / 删除多少图元”，用户确认后才提交。
3. 一批动作只调用一次 `commitAction`，因此一次 `Ctrl/Cmd + Z` 可以整体回退。
4. `CLEAR` 与删除数量 ≥ 5 的批量删除必须显式勾选确认，确认按钮才可用。
5. 用户取消预览时不产生任何状态变更，也不写入撤销历史。

## 理由

- 预览让 AI 的意图与执行结果对用户可见，降低误删风险。
- 单次提交保证撤销粒度与用户心智一致：一次 AI 请求 = 一步操作。
- dry-run 是纯函数，可以脱离 UI 用固定样例回归测试。
- 高风险操作单独确认，避免“确认预览”被理解为无条件执行。

## 后果

- AI 动作必须能表达为可 dry-run 的纯变换；依赖外部状态的动作无法直接接入。
- 预览与实际提交之间理论上存在画布变化，提交时需基于同一快照校验。
- 大批量动作的预览需要统计而非渲染全部图元，避免卡顿。
- 删除确认阈值（5）是产品参数，调整时需同步测试与文档。
