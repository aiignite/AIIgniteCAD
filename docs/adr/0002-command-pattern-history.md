# ADR 0002：使用命令模式实现撤销 / 重做

- **状态**：Accepted
- **日期**：2026-10-21
- **决策者**：前端团队

## 背景

画布早期使用整份元素快照实现撤销，简单可靠，但每次编辑都复制完整数组：大图纸下内存与比较成本高，且属性面板连续输入会产生大量无意义历史节点。

## 决策

以 `lib/command.ts` 定义命令接口（`do` / `undo`），`canvasStore` 默认记录增量命令；同时保留 `VITE_HISTORY_MODE=snapshot` 环境变量回退到快照模式。

## 理由

- 命令只保存必要的前后差异，内存占用与图纸大小解耦。
- 连续属性输入可以合并为一个命令（当前通过 400ms 防抖提交）。
- 快照回退开关降低迁移风险，便于定位历史相关缺陷。
- 命令层是纯函数，可在 Node 环境中直接测试。

## 后果

- 每种新编辑操作都必须正确实现正向与逆向逻辑，测试成本高于快照。
- 命令粒度需要刻意设计：过细导致撤销步数过多，过粗导致用户无法回退单步。
- 批量操作（阵列、偏移、AI 批量应用）需要作为一个命令提交。
