# ADR 0015：设计约定、版本记忆、多方案与参考图矢量化

- 状态：已采纳
- 日期：2026-10-22
- 相关：ADR 0006（上下文摘要）、ADR 0010（Agent 循环）、ADR 0013（技能与设计上下文）、ADR 0014（计划模式与检查面板）

## 背景

P1 让 AI 能查、量、检、规划和执行，但每次对话仍缺少三类“项目连续性”：

1. 项目有自己的制图标准、图层命名与字高要求，模型每次只能重新猜测。
2. 版本历史只保存快照，模型不知道最近改了什么，难以延续上一轮设计。
3. 布局类问题通常有多种解法，直接执行一个方案会让用户失去比较机会；
   同时，用户手上的参考图（截图、扫描草图）无法进入 CAD 流程。

## 决策

### 1. 设计约定随项目存储并注入提示词

- `projects.design_conventions` 保存标准、单位、建议字高、尺寸精度、图层规则与备注。
- 前端“约定”面板编辑后由 IndexedDB 本地落地，并通过既有项目同步队列写回服务端；
  离线创建的本地 id 回填服务端 id 后，约定不丢失。
- 服务端 `normalizeDesignConventions` 对长度、数量、枚举与数值范围做边界校验；
  空约定折叠为 `null`。
- `llmChat` 按 `projectId` 校验归属后读取约定，`promptComposer` 以高权重段落注入；
  约定不是硬约束，用户明确要求优先。

### 2. 版本记忆只保存可解释的变更摘要

- `project_versions.change_summary` 记录相对上一版本的新增/删除数量、类型分布与涉及图层。
- 摘要只比较 id、类型与图层，不做几何深比较，避免版本创建成本失控。
- 版本列表与详情返回摘要，前端历史列表显示 `+N / -M`。
- 每轮对话读取最近 5 个版本，以“vN（日期）：+a / -r；新增类型；涉及图层；备注”注入提示词。

### 3. 多方案是“一次提案、本地分叉预览、选择一个执行”

- 新增 `propose_variants` 控制工具；`variantMode` 请求只下发只读工具与该工具，禁止直接写画布。
- 服务端 `normalizeVariants` 限制 2–3 个方案、名称唯一、每个方案 1–12 个合法步骤；
  步骤工具必须在 CAD 工具白名单内。
- 前端解析后为每个方案在**当前图纸**上独立执行 `applyToolCalls`，用生成的变更图元做缩略预览；
  方案之间互不影响。用户选择一个方案后只走一次 `AIPreviewModal` 与一次 `commitAction`。
- 方案对比卡片只存在于当前会话视图，不额外落库；服务端仍保存模型原始 toolCall 供审计。

### 4. 参考图转 CAD 在本地确定性完成

- `lib/imageTrace.ts` 对 RGBA 像素做亮度二值化，使用 marching squares 提取轮廓，
  Ramer–Douglas–Peucker 简化后输出 `LWPOLYLINE`。
- 图片在浏览器内缩放、读取与追踪，不上传服务器；阈值、反色、简化容差与目标宽度可调。
- 插入结果作为一批图元 `commitAction`，支持预览、选中与一步撤销。
- 该能力是“轮廓描图”，不承诺识别尺寸/语义；复杂照片需要用户先做线稿化。

## 后果

- 项目级约定与版本记忆让模型具备跨轮、跨版本的连续性，但会增加系统提示词长度；
  约定与版本摘要都经过长度限制，且在预算裁剪中优先于低权重段落。
- 多方案模式多一次用户选择，但避免多个方案互相污染；只有明确“方案对比”类请求才触发。
- 参考图矢量化受图像质量影响，输出是近似轮廓；用户需要在预览中确认后再插入。
- 新增约定、版本摘要字段需要迁移；本地/服务端项目同步与本地 id 回填需保持约定字段透传。
- 同步队列必须保证「进行中 flush 期间到达的保存请求」不被丢弃，否则约定等元数据改动会滞留本地；
  该约束由 `syncService` 的补跑机制与 `tests/syncService.test.ts` 回归用例守住。
- 测试覆盖：`tests/aiVariants.test.ts`、`tests/imageTrace.test.ts`、
  `backend/tests/designConventions.test.ts`、`backend/tests/versionMemory.test.ts`、
  `tests/e2e/conventions.spec.ts`、`tests/e2e/trace.spec.ts` 与 `tests/e2e/aiChat.spec.ts`。
